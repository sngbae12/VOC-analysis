# 고객사 VOC 분석 웹앱

업로드한 VOC CSV로 항목별 비율, 불만 키워드 그림, 한글 워드 보고서를 만드는 Gradio 웹앱입니다.

**GitHub 저장소는 소스 배포용입니다.** 클라우드에서 분석이 돌아가거나, GitHub이 고객 데이터를 받아 처리하지는 않습니다. 각 사용자는 ZIP 또는 `git clone`으로 소스를 받은 뒤 **자신의 Windows(또는 지원 Python이 있는) 컴퓨터에서** 앱을 실행합니다.

이 저장소의 샘플은 가상으로 만든 연습 데이터입니다. 실제 고객 데이터는 포함되어 있지 않습니다.

## 구현된 기능

- CSV 업로드 또는 실습 샘플 적용. 새 데이터는 기존 데이터를 **교체**하며 행을 누적하지 않습니다.
- 산업군·제품명·분야별 VOC 건수와 비율(%) 표, 화면용 Plotly 막대그래프
- 불만 열 기준 키워드 워드클라우드
- 통계·그림·이슈 요약을 담은 `.docx` 보고서
- 업로드 실패 후에도 이전 데이터를 유지하고, 다른 파일이나 같은 파일을 다시 적용할 수 있음

구현하지 않은 기능(로그인, 다중 사용자 저장소, GPU 추론, 자동 분류 모델 학습)은 제공하지 않습니다.

## 기술 스택과 분석 흐름

| 구성 | 실제 사용 |
|---|---|
| 화면 | Gradio 6 Blocks |
| 표·통계 | pandas |
| 화면 막대그래프 | Plotly (브라우저에서 그림) |
| 보고서용 PNG | matplotlib (Chrome 불필요) |
| 워드클라우드 | wordcloud, matplotlib |
| 보고서 | python-docx |
| 이슈 문장만 | CrewAI + OpenAI `gpt-4o-mini`(기본) |

1. **데이터 불러오기**: CSV를 읽고 필수 열을 확인한 뒤 메모리에 **교체** 저장합니다.
2. **통계분석**: pandas로 비율을 계산하고 Plotly 그래프를 화면에 표시합니다. 보고서용 PNG는 matplotlib로 저장합니다. OpenAI는 호출하지 않습니다.
3. **워드클라우드**: 불만 문구를 이 컴퓨터에서 토큰화해 그림을 만듭니다. OpenAI는 호출하지 않습니다.
4. **보고서생성**: 통계·워드클라우드·DOCX는 이 컴퓨터에서 만듭니다. API 키가 있을 때만 이슈 문장을 OpenAI에 요청하고, 그 **이번 작업** 내용으로 DOCX를 다시 저장합니다.

GPU는 쓰지 않습니다. Chrome이 없어도 통계·워드클라우드·보고서는 동작합니다.

### 외부로 전송되는 내용

OpenAI를 호출할 때 **CSV 파일 전체는 업로드하지 않습니다.** `build_voc_digest()`가 만든 요약만 이슈 생성 프롬프트에 들어갑니다.

- VOC 총건수, 기간, 산업군·제품·분야 고유 값 수
- 산업군·분야·제품명별 건수와 비율
- 산업군별 **대표 불만 문구**(산업군 최대 8개, 각 4건)
- 불만 키워드 상위 25개

`고객명`, `지역`, `순번` 열은 요약에 넣지 않습니다. 다만 **불만 문구 안에 이름·연락처 등 개인정보가 있으면 그대로 전송될 수 있습니다.**

인터넷이 필요한 단계: 이슈 문장용 OpenAI 호출뿐입니다.

```
VOC-analysis/

  sample_voc.csv        가상 실습 샘플 (50건)
  requirements.txt      직접 import하는 패키지 (UTF-8)
  setup.bat             Windows 가상환경 생성·패키지 설치
  start.bat             Windows 실행 (.venv Python 우선)
  .env.example          환경 변수 예시 (키 값은 비움)
  tests/                회귀 테스트
  README.md

```

`output/`은 없으면 앱이 만듭니다.

## 지원 Python 버전

검증·권장: **Python 3.11** (작성 환경: 3.11.9)

지원: **3.11, 3.12, 3.13**

지원하지 않음: 3.10 이하, **3.14 이상**. 고정된 CrewAI 1.15.1의 조건은 `>=3.10,<3.14`이고, pandas 3.0은 3.11 이상이 필요합니다. 두 조건을 맞춘 범위가 3.11~3.13입니다.

`setup.bat`과 `start.bat`은 지원하지 않는 버전이면 설치·실행 전에 이유를 보여 줍니다.

## 설치와 실행 순서

Windows에서 처음이라면:

1. Python 3.11을 설치합니다.
2. 저장소를 clone 하거나 ZIP을 풉니다.
3. `setup.bat`을 더블클릭합니다. 프로젝트 `.venv`를 만들고 `requirements.txt`를 설치합니다.
4. `start.bat`을 더블클릭합니다. `.venv\Scripts\python.exe`를 우선 사용합니다.
5. 브라우저에서 [http://127.0.0.1:7860](http://127.0.0.1:7860) 을 엽니다.

수동 설치:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\activate
python -m pip install -U pip
python -m pip install -r requirements.txt
python -m pip check
python voc_analysis_app.py
```

`requirements.txt`는 UTF-8입니다. 이 앱이 직접 쓰는 패키지와 작성 시 확인한 버전만 적었습니다. 개발 PC의 전체 pip 목록은 넣지 않았습니다. 전역 패키지에 의존하지 않습니다.

## 한글 폰트

워드클라우드와 보고서 PNG는 한글 폰트가 필요합니다.

- Windows: 기본적으로 `Fonts`의 맑은 고딕(`malgun.ttf`)을 등록합니다.
- Linux(CI·Ubuntu): NanumGothic 등 (`fonts-nanum`)을 찾습니다.
- 사용자 지정: 환경 변수 `VOC_FONT_PATH`에 `.ttf`/`.ttc` 전체 경로를 지정합니다.

폰트를 찾지 못하면 앱은 뜰 수 있지만 워드클라우드는 실패합니다. 통계 표와 화면 그래프는 만들 수 있습니다. `VOC_FONT_PATH` 예시는 `.env.example`을 참고하세요. 사용자가 만든 `.env`는 앱이 수정하지 않습니다.

## 모델·API 준비

로컬 LLM 파일이나 Hugging Face 모델은 **필요하지 않습니다.**

키 **없이** 되는 기능: 데이터 적용, 통계, 워드클라우드, 통계·그림이 들어간 DOCX 저장.  
OpenAI 키가 **필요한** 기능: 보고서의 이슈 문장(4~5장).

1. 앱 상단 **OpenAI API 키** 칸에 본인 키를 입력합니다. **기본값은 비어 있습니다.**
2. 비우면 환경 변수 `OPENAI_API_KEY`를 사용합니다. 사용자가 직접 만든 `.env`가 있으면 프로젝트 폴더 기준으로 읽습니다.
3. 앱은 키를 파일, 로그, Git, URL, 브라우저 저장소에 쓰지 않습니다. 화면에서 입력한 키는 해당 보고서 작업이 끝나면 입력란에서 지웁니다.
4. **사용자가 만든 `.env`나 환경 변수 파일은 앱이 수정하지 않습니다.**
5. 모델 이름은 기본 `gpt-4o-mini`이며, `OPENAI_MODEL_NAME`으로 바꿀 수 있습니다.

키가 없거나 이슈 생성이 실패해도 이번 작업의 워드 파일은 이 컴퓨터에서 만듭니다. 미리보기와 DOCX에는 이슈 실패 안내가 들어가며, 이전 이슈를 성공 결과처럼 보여 주지 않습니다.

## 샘플로 확인하는 사용 순서

1. `start.bat`으로 앱을 엽니다.
2. **실습 샘플 불러오기**를 누릅니다. 선택됨 표시와 50건 미리보기를 확인합니다.
3. **통계분석**에서 기준을 고르고 비율을 계산합니다. (키 없음, OpenAI 호출 없음)
4. **워드클라우드**에서 키워드 그림을 만듭니다. (키 없음, OpenAI 호출 없음)
5. **보고서생성**에서 키를 비운 채 보고서를 만듭니다. DOCX가 저장되고, 이슈 문장은 없다는 안내가 붙습니다.

## 지원 CSV 스키마와 날짜 형식

지원 형식: **`.csv`만**. 인코딩은 UTF-8(BOM 포함), UTF-8, CP949, EUC-KR 순으로 시도합니다.

필수 열:

| 열 | 형식 | 설명 |
|---|---|---|
| 순번 | 값 있음 | 식별용 |
| 일자 | 아래 날짜 형식 | 잘못된 값·빈 값은 기간 계산에서 빠짐. 행은 불만이 있으면 유지 |
| 고객명 | 문자열 | 화면 미리보기용. OpenAI 요약에는 넣지 않음 |
| 산업군 | 문자열 | 통계 기준 |
| 지역 | 문자열 | 화면 표시 |
| 제품명 | 문자열 | 통계 기준 |
| 분야 | 문자열 | 통계 기준 |
| 불만 | 문자열 | 내용이 있는 행만 분석. 이슈 요약에 대표 문구로 들어갈 수 있음 |

지원 일자:

- `YYYYMMDD` 정수 또는 문자열 (예: `20260101`)
- `YYYY-MM-DD` (예: `2026-01-01`)
- `YYYY/MM/DD`, `YYYY.MM.DD`

한 파일에 위 형식이 섞여 있어도 됩니다. pandas가 큰 정수를 나노초 시각으로 읽어 1970년으로 바꾸는 경로는 쓰지 않습니다.

유효하지 않은 날짜(예: `20261399`, `어제`)와 빈 칸은 기간에서 제외하고, 제외 건수를 화면 개요에 안내합니다. 앱 전체가 멈추지는 않습니다. 화면 기간, 통계 요약, OpenAI로 보내는 요약, DOCX의 기간은 같은 해석 결과를 씁니다.

xlsx, 빈 파일, 필수 열 누락, 깨진 CSV는 화면에서 이유를 보여 주고, 이미 적용된 데이터가 있으면 그 데이터를 유지합니다.

## 데이터 보관·다운로드·임시 파일 정책

| 위치 | 내용 | 브라우저 파일 제공 |
|---|---|---|
| 메모리 `STORE` | 현재 적용된 표와 분석 결과. 새 파일/샘플로 **교체** | 해당 없음 |
| `output/uploads/` | 업로드 원본 복사, 현재 적용 CSV | 제공하지 않음 (403) |
| `output/exports/` | 이번 앱 실행이 만든 PNG·DOCX | 화면 표시·다운로드 (등록된 결과만) |
| Gradio 임시 업로드 캐시 | 파일 선택 시 Gradio가 OS 임시/캐시 폴더에 만드는 복사본 | **원본 CSV는 제공하지 않음 (403)** |
| Gradio가 만든 결과 파일 캐시 | 화면에 올린 PNG·DOCX의 임시 복사 | 내용이 앱이 등록한 결과와 같으면 허용 |
| 프로젝트 `.env`, `.git`, `.venv`, 소스 | 비밀·코드 | 제공하지 않음 (403) |

다운로드 허용은 확장자만 보지 않습니다. 앱이 PNG·DOCX를 저장할 때 파일 내용의 SHA-256을 등록하고, 그 내용과 같은 파일만 파일 인터페이스로 줍니다. 임의의 `.png`/`.docx`나 업로드 CSV는 막습니다.

앱은 `output/uploads/`와 `output/exports/`를 **자동으로 지우지 않습니다.** Gradio 임시 캐시는 Gradio/OS 정책에 따르며, 이 앱이 원본 CSV를 그 캐시에서 다운로드용으로 등록하지는 않습니다. 공유·반납 전에 업로드 원본은 사용자가 직접 지우세요.

Git에는 `output/`과 `.env`를 올리지 않습니다.

## 흔한 오류와 해결

| 상황 | 안내 |
|---|---|
| Python 3.14 | 설치 전에 지원 버전 안내. 3.11로 다시 `setup.bat` |
| 패키지 없음 | `setup.bat` 실행. `start.bat`은 `.venv` Python을 우선 사용 |
| 포트 7860 사용 중 | 실행 중인 앱을 종료하거나 그 주소로 접속 |
| 한글 폰트 없음 | Windows 맑은 고딕 확인, 또는 `VOC_FONT_PATH` |
| 한글·공백 경로 | `setup.bat`/`start.bat`은 스크립트 위치 기준으로 동작 |
| 워드클라우드 실패 | 통계와 가능한 그림으로 DOCX는 저장. 완전한 보고서로 표시하지 않음 |
| 이슈 생성 실패·시간 초과 | 이번 실패 안내로 DOCX 저장. 이전 이슈를 성공처럼 쓰지 않음 |
| 잘못된 CSV | 기존 데이터 유지 후 재시도 |

## 확인한 테스트와 미검증 항목

저장소 `tests/`와 GitHub Actions(`ubuntu-latest`, `windows-latest`, Python 3.11)에서 다음을 검증합니다.

- Gradio 임시 업로드 캐시의 원본 CSV HTTP 403, 적용 후에도 동일
- `.env`/소스/샘플 CSV/업로드 복사본 403, 앱이 만든 PNG·DOCX 200, 해시가 같은 Gradio 캐시 PNG 200, 미등록 PNG/DOCX 403
- YYYYMMDD 정수·문자열, ISO, 슬래시·점 구분, 빈 값, 잘못된 날짜, 혼합 형식. 화면·요약·DOCX 기간 일치
- 워드클라우드 실패, 통계 PNG 실패, 모든 그림 실패 시에도 DOCX 저장. 불완전 표시
- 이슈 시간 초과 후 이전 이슈·이전 파일을 성공 결과로 반환하지 않음
- 샘플 50건, 교체 적용, 같은 파일 재적용, 실패 후 기존 유지, 버튼 활성화 복구
- 키가 있어도 통계·워드클라우드에서 LLM/API 미호출
- HTML이 포함된 파일명·CSV 값 이스케이프
- Python 3.14 거절, 3.11 허용
- Gradio TestClient로 홈 페이지 200

구분:

- **실제 실행**: 로컬 함수, pandas 날짜, DOCX 저장, SHA-256 다운로드 가드, FastAPI TestClient를 통한 Gradio `file=` HTTP
- **대역(mock)**: 이슈 생성 실패·시간 초과, 워드클라우드/PNG 강제 실패, LLM 생성 차단
- **미검증**: 실제 유료 OpenAI 호출, 다른 사용자의 실제 Windows PC 첫 설치 전체 화면 클릭, Cursor 브라우저 자동화로 버튼 전 구간 조작(이 안내를 작성하는 시점의 기본 회귀는 TestClient·함수 테스트)

## 현재 제한사항

- 한 번에 하나의 VOC 집합만 다룹니다. 여러 파일을 합치지 않습니다.
- 외부 공개 주소가 아니라 `127.0.0.1`에서만 엽니다.
- 한글 워드클라우드·보고서는 한글 폰트에 의존합니다.
- 이슈 문장 품질은 모델과 네트워크에 따라 달라집니다.
- 그림이 빠진 보고서는 저장되지만 완전한 보고서로 표시하지 않습니다.
- 업로드된 실제 고객 데이터는 `output/uploads/`에 남습니다. 공유 전에 직접 지우세요.
